## Контекст

Стример выбирает технику голосованием зрителей и хочет сам менять коэффициенты (R10i); зрители должны видеть выставленное сразу (R11i). До этого были 10 скриншотов дерева, которые долго собирать и неудобно менять.

## Решение

Сайт — один сервер в Docker-контейнере. Стример входит по паролю из `ADMIN_PASSWORD` и правит значения прямо на сайте, зрители читают те же значения с того же сервера. Статический сайт, где значения правятся вне страницы, не выбран.

## Почему

В манифесте записано: на вопрос «кто и как выставляет и меняет коэффициенты» пользователь выбрал «Сервер с паролем» (R10i); основание для R11i — «зрители видят изменения сразу». Пользователь выбирал из трёх вариантов: редактор + файл, редактор + ссылка, без редактора.

Чем не подошли:
- **Без редактора.** Значения остались бы такими, как на скриншотах. Это противоречит задаче: «Стример меняет значения сам».
- **Редактор + файл и редактор + ссылка.** Отдельные причины отказа от каждого в источниках не записаны. Общий записанный довод один: R11i требует, чтобы зрители видели изменение сразу, а оба варианта оставляют отдельный шаг между правкой стримера и тем, что видит зритель. Это вывод из R11i, а не цитата.

Из «Вне рамок»: один пароль на всех, кто правит, без ролей и нескольких модераторов.

## Последствия

- Нужен работающий сервер: контейнер, том `./data` для значений и истории, на VPS — nginx перед ним (G03). Статический хостинг больше не подходит.
- Появилась защита, которой у статики не было бы: пароль, подписанная сессия на 30 дней, лимит неверных паролей, проверка `Origin`, ограничение тела запроса. Каждое — место для ошибки.
- Без `ADMIN_PASSWORD` сайт только для просмотра. Если `SESSION_SECRET` не задан, секрет случайный на запуск, и после каждого перезапуска стримеру надо входить заново.
- Один пароль на всех правящих: кто что менял, сайт не различает.
- Файл значений (скачать и загрузить) остаётся способом сохранить и перенести состояние. Он дополняет сервер, но не заменяет его.
