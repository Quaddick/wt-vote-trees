## Контекст

Всё о деревьях берётся из вики War Thunder (R07), парсер и иконки уже есть в WT_wheel_k2 (R06). Правило проекта: рантайм в интернет не ходит, к вики обращается только сборщик каталога.

## Решение

Каталог (деревья, иконки-слоты, флаги) собирается заранее командой `npm run catalog` и лежит в репозитории. Docker-сборка и запуск сервера к вики не обращаются.

## Почему

В спецификации записано: «Docker-сборке и запуску вики не нужна». Там же сказано: если вики недоступна, сборка каталога падает с ошибкой, а старый каталог остаётся целым.

Чем не подошло: **запрашивать вики при сборке образа или при старте сервера.** Тогда недоступность вики (или смена её вёрстки) ломала бы сборку или запуск сайта. В источниках это прямо не сказано, это вывод из правила «рантайм в интернет не ходит». Сам сайт при этом не получил бы ничего, чего нет в предсобранном файле.

## Последствия

- В git лежат `trees.json`, иконки и флаги: 1227 машин, репозиторий вырос на их размер.
- Каталог — снимок на день сборки. Новая техника в игре появится на сайте только после `npm run catalog` (нужна сеть), коммита и пересборки образа. Новые машины встают со значением «1», значения остальных сохраняются, пропавшие из дерева машины скрываются, их значения остаются в файле (R07.1).
- Парсер завязан на вёрстку вики. Если вики её поменяет, сборка сломается, пока не поправят парсер; от этого есть только фикстуры HTML в тестах.
- Иконки берутся из папки слотов колеса WT_wheel_k2 (переменная `WHEEL_SLOTS_DIR`), недостающие докачиваются. Это зависимость от соседнего проекта на диске.
- Часть данных вики неполна: у 10 пусковых установок ЗРК нет БР (на карточке «—»), у 3 машин нет иконки (нужна заглушка).
