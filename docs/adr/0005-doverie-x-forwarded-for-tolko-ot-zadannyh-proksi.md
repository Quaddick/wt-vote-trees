## Контекст

Пять неверных паролей с одного IP за 10 минут закрывают вход (R10i.5). На VPS сайт стоит за nginx, а контейнер слушает только `127.0.0.1:8080`, поэтому адрес соединения — это адрес прокси, а не клиента.

## Решение

Заголовок `X-Forwarded-For` читается только тогда, когда соединение пришло с адреса из `TRUSTED_PROXIES` (адреса или подсети через запятую или пробел). По умолчанию список пуст, и заголовок не читается совсем.

## Почему

В источниках записано только решение: появилось на «ремонте» после сборки сервера, по умолчанию список пуст. Причины там нет, дальнейшее — вывод из лимита и порта.

Чем не подошло:
- **Всегда верить `X-Forwarded-For`.** Заголовок подставляет любой клиент. Каждый запрос он мог бы подписать новым адресом и обойти лимит, а значит, подбирать пароль без ограничений.
- **Никогда не читать заголовок.** За nginx все зрители и стример выглядят одним адресом прокси. Пять чужих неверных попыток закрыли бы вход стримеру.

## Последствия

- На VPS оператор должен вписать адрес nginx в `TRUSTED_PROXIES`. Без этого лимит общий на всех, и посторонний может заблокировать вход стримеру на 10 минут.
- Слишком широкая подсеть в списке возвращает подмену адреса. Настройку нельзя «на всякий случай» открыть для всех.
- Локально (`docker compose up` без nginx) всё работает с пустым списком. Ошибка проявится только после выкладки за прокси.
