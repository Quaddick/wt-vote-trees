# Как запустить и выложить сайт

Сайт — один Docker-контейнер: он раздаёт страницу и API на порту 8080. Значения машин и история правок лежат в папке `data/runtime/` на хосте, поэтому контейнер можно пересобирать и удалять, данные останутся.

## 1. Файл `.env`

Рядом с `docker-compose.yml` создай файл `.env` (образец — `.env.example`):

```
ADMIN_PASSWORD=<придумай пароль стримера>
SESSION_SECRET=<длинная случайная строка>
```

- `ADMIN_PASSWORD` — пароль для входа в режим правки. Пусто — кнопки «Вход» нет, сайт только показывает значения, в логе контейнера будет предупреждение.
- `SESSION_SECRET` — секрет, которым подписаны сессии. Сгенерировать: `openssl rand -hex 32`. Пусто — секрет новый при каждом запуске, и после перезапуска контейнера придётся войти снова.

`.env` в git не попадает. Пароль меняется правкой `.env` и командой `docker compose up -d` — старые сессии продолжат действовать, пока не сменишь и `SESSION_SECRET`.

## 2. Запуск

```
docker compose up -d --build
```

Сайт откроется на `http://localhost:8080`. Проверить, что живой: `curl http://localhost:8080/api/state` или `docker compose ps` (статус `healthy`). Лог — `docker compose logs -f`.

Порт открыт только для этой машины (`127.0.0.1:8080`). Чтобы зайти с другого устройства в локальной сети без nginx, в `docker-compose.yml` замени `"127.0.0.1:8080:8080"` на `"8080:8080"` (тогда `TRUSTED_PROXIES` оставь пустым, см. раздел 4).

### Первый запуск

Если `data/runtime/values.json` нет, сервер берёт стартовые значения со скриншотов (`data/seed/values.json`, вшиты в образ при сборке). Если и их нет — у всех машин «1», в логе предупреждение. История в начале пустая.

### Если сервер не стартует

- `Битый JSON в файле …/values.json` (или `changes.json`) — файл испорчен; сервер его не трогал. Восстанови из бэкапа или удали (тогда значения снова возьмутся со скриншотов, история пропадёт).
- `EACCES … data/runtime` — у контейнера нет прав писать в папку. Контейнер работает от пользователя с UID 1000: `sudo chown -R 1000:1000 data/runtime`.

## 3. Обновление

```
git pull
docker compose up -d --build
```

Значения в `data/runtime/` сохраняются. Новые машины из обновлённого каталога получают «1», машины, пропавшие из дерева, не показываются, но их значения остаются в файле.

Каталог деревьев (`public/catalog/`) вшивается в образ при сборке; после `npm run catalog` и коммита нужен тот же `docker compose up -d --build`.

## 4. VPS за nginx

1. На VPS: Docker с плагином compose, nginx, домен, указывающий на сервер.
2. Склонировать репозиторий, создать `.env` (пункт 1), запустить `docker compose up -d --build`. Клонируй от обычного пользователя, не от root: тогда папка `data/` принадлежит UID 1000, и контейнер сможет в неё писать.
3. Конфиг nginx, например `/etc/nginx/sites-available/wt-vote`:

```nginx
server {
    listen 80;
    server_name vote.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 1m;
    }
}
```

4. Включить и выпустить сертификат: `ln -s /etc/nginx/sites-available/wt-vote /etc/nginx/sites-enabled/ && nginx -t && systemctl reload nginx`, затем `certbot --nginx -d vote.example.com`.

Что важно в конфиге:
- `Host $host` — сервер сверяет `Origin` изменяющих запросов с `Host`; без этой строки вход и правки получат отказ «Запрос с чужого сайта».
- `X-Forwarded-Proto $scheme` — по нему cookie сессии получает флаг `Secure` при https.
- `X-Forwarded-For` — по нему считается лимит неверных паролей (5 за 10 минут с одного IP), но только если в `.env` задан `TRUSTED_PROXIES` (см. ниже).

### `TRUSTED_PROXIES` — кому верить в `X-Forwarded-For`

По умолчанию переменная пустая, и сервер этот заголовок не читает. Лимит попыток считается по адресу соединения, поэтому подставить чужой IP в заголовок и обойти лимит нельзя. Минус в том, что за nginx у всех посетителей один адрес — адрес nginx. Пять чужих неверных паролей запирают вход на 10 минут и для стримера.

Чтобы считать лимит по настоящему IP посетителя, впиши в `.env` адрес, с которого nginx приходит в контейнер. Это шлюз docker-сети контейнера:

```
docker inspect -f '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}' wt-vote-trees
```

Например, вывод `172.18.0.1` даёт строку `TRUSTED_PROXIES=172.18.0.1` в `.env`, после неё нужен `docker compose up -d`. Несколько адресов пишутся через запятую, можно указать IPv4-подсеть (`172.18.0.0/16`). В заголовке сервер берёт последний адрес — тот, что дописал nginx; всё, что левее, мог подставить сам посетитель.

Задавай `TRUSTED_PROXIES` только когда порт опубликован как `127.0.0.1:8080:8080` и в контейнер ходит один nginx. Если открыть порт наружу (`8080:8080`), прямые подключения в некоторых конфигурациях Docker (Docker Desktop, userland-proxy) тоже приходят с адреса шлюза. Тогда посетитель снова сможет подменить заголовок. С открытым портом оставляй `TRUSTED_PROXIES` пустым.

## 5. Бэкап

Всё, что нужно сохранить, — два файла в `data/runtime/`: `values.json` (значения) и `changes.json` (история, последние 1000 записей). Пишутся атомарно, копировать можно на ходу:

```
tar czf wtv-backup-$(date +%F).tar.gz data/runtime
```

Например, раз в сутки через cron. Восстановление: `docker compose down`, распаковать архив на место `data/runtime/`, `docker compose up -d`.

Дополнительно можно скачать значения кнопкой «Скачать значения» в режиме правки — этот файл загружается обратно кнопкой «Загрузить».
